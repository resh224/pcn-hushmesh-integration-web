      How do they talk?A proposed adapter translates between the two sides. This demo models HTTPS requests carrying JSON, plus application replies. Native vendor endpoints, authentication and delivery contracts still need confirmation.
      What is documented, and what is proposed?
      Documented: the supplied PCN wiki describes a Platform / Supplier Backend API proof of concept (p. 142). Hushmesh’s OIDC sample describes sign-in, not this data exchange.
      Proposed here: a REST-style HTTPS/JSON bridge. These are logical service names, not real URLs or supported endpoint contracts. No live request is sent. Webhooks, queues or a vendor SDK could replace a leg after partner validation. The dashed return path is an application acknowledgment, not proof of an HTTP status or business truth.
      Data custody: “PCN-side” includes the owner’s storage service. It does not mean PCN’s ledger stores or serves the original file.
